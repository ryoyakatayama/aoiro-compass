# 青色コンパス / Aoiro Compass

v0.3では、スマホから原本を検索して確認事項へ回答できる[過年度資料台帳](SOURCE_ARCHIVE.md)を追加しました。台帳と回答は帳簿のDrive同期に含まれます。過年度の月次集計では未集計と0円を区別し、年末按分や返金によるマイナスにも対応します。

個人事業と雑所得の記帳、領収書管理、数字の振り返り、税務相談の準備をつなぐPWAです。Google Driveを正本・バックアップの保存先とし、端末に操作用の作業データを持ちます。

**[GitHub Pagesでの導入・復旧手順](DEPLOYMENT.md)** / [セキュリティ](SECURITY.md) / [検証記録](VALIDATION.md)

**事業所得（青色申告）と雑所得は、SQLite・原本キュー・事業プロフィール・相談・バックアップを分けて保存します。** スマホでも画面上部または証憑画面の「取込先」で切り替えられます。

## はじめる

Node.js 22.12以上とpnpmを使用します。

```sh
pnpm install
pnpm dev
```

開発画面は `http://127.0.0.1:5173`。通常起動では帳簿は空です。`?demo=1` で架空の事業データを使って試せます。デモは実帳簿と別領域です。雑所得は `?book=misc`、雑所得デモは `?book=misc&demo=1`。

```sh
pnpm test
pnpm build
pnpm preview
```

本番プレビューは `http://127.0.0.1:4173`。開発用と本番用は生成元が異なるため、帳簿の保存先も別です。必要に応じてSQLiteのバックアップ・復元で移行してください。

ブラウザの統合テスト:

```sh
pnpm exec playwright install chromium
pnpm build
pnpm test:e2e
```

Windowsでインストール済みのEdgeを使う場合は `PLAYWRIGHT_CHANNEL=msedge` を設定して実行できます。テストは独立したブラウザコンテキストを使用します。

## できること

- **事業と雑所得を分離**：画面上部と領収書の取込前に切替。収入・経費・差引額を個別集計。
- **ダッシュボード**：月次の売上・経費・利益、前年売上、年累計/当月、利益率、経費内訳、現預金・売掛金。
- **複式簿記**：複合仕訳、期首残高、任意の科目追加、下書き・確定・ロック。借貸不一致の確定は拒否。確定後の修正は理由と変更前データを記録。
- **領収書**：カメラ、複数ファイル、PDF/JPEG/PNG/WebP/HEIC、端末への先行保存、オフラインキュー、再接続時アップロード、Driveで追加したファイルの同期、UUID・Drive ID・SHA-256による識別。
- **AI読取**：選択した原本と読取スキーマをZIP出力。JSONLを検証して候補として取込。人が下書きを開いて確認・確定。スマホでも仕訳の入力中に新しい勘定科目を登録し、その場で利用できます。
- **銀行・カード**：UTF-8/Shift JISの汎用CSV、列名指定、取込プレビュー、重複バッチ拒否、口座・金額・前後7日の仕訳候補と手動照合。
- **固定資産**：台帳、供用日、事業割合、手動で確認した年度別償却額・ルール・根拠、事業分と私用分を分けた下書き。
- **帳簿**：P/L、B/S、試算表、総勘定元帳、年度比較、期首と期末の継続性。CSV/JSON出力、表示中の帳簿を印刷/PDF保存。
- **過年度**：検証済み汎用JSONから年次集計または仕訳、固定資産を取り込み、閲覧専用で保持。
- **AI税務相談**：業種・仕事内容・顧客・収益モデル・働き方・私用との混在・税務状況を入力。7種類の相談、対象年度・期間・科目・仕訳の指定、パックのプレビューとZIP出力。
- **指摘への対話**：AI指摘ごとの回答・追加質問、全体の相談、履歴を含む対話パック、返信先を検証した追加回答取込、解決・保留などの状態、修正案の下書き、選択した追加証憑パック。
- **年度締め**：チェック、Driveへの事前バックアップ、チェックサム付きアーカイブを保存後ロック。理由を残した解除、元入金への振替を含む翌期繰越。
- **自動同期・復旧**：帳簿・科目・プロフィール・相談をDrive経由で同期。別々の編集は合成し、重なる変更は両方を保持して確認。同期後にDriveへSQLiteバックアップを残し、新端末や壊れた端末を専用画面から復旧できます。
- **仕訳の素早い編集**：確定済みを直接修正、複製、借貸への同額入力、科目の絞り込み、理由の候補、保存して次へ・連続入力。Ctrl/Cmd+Enterで確定、Shiftも押すと連続入力、Ctrl/Cmd+Sで下書き保存。編集中の破棄は確認します。

## 領収書から経費計算まで

1. 「事業所得」または「雑所得」を選びます。
2. 「証憑ライブラリ」で科目と支払元のヒントを選び、撮影またはファイル追加します。
3. 必要に応じてDrive同期し、原本を保存します。
4. 証憑を選択して「AI読取パック」を保存し、ChatGPTへ添付します。
5. ChatGPTから得たJSONLを「AI読取結果を取り込む」で戻します。
6. 候補から下書きを作り、日付・科目・金額を確認して確定します。
7. ダッシュボードと帳簿画面に、確定済みの収入・経費・差引額が反映されます。

AIを使わず「取引を記帳」から入力し、仕訳の詳細で証憑を紐付けることもできます。

## 領収書を1件ずつ連続仕訳する

AI読取結果の取込後、「証憑ライブラリ」または「仕訳・記帳」の **領収書を連続仕訳** を押します。未処理の読取候補と、原本付きの下書きを日付順に確認できます。科目未登録のAI候補でも、ここで人が科目を選べます。

支払側（貸方）は **事業主借** が初期値で、連続処理中は同じ設定を使います。原本を表示し、金額・日付・摘要を確認して借方の経費科目を選び、「確定して次へ」で進めます。前と同じ科目、科目検索、その場での科目追加、保留、Ctrl/Cmd+Enterにも対応します。保留分は次回に残ります。売上・複合仕訳や原本の問題は詳細編集で確認します。

## 年度末の事業主勘定

「年度締め → 事業主借の精算・調整」で、残高・仕訳・処理後の残高を見ながら次をワンクリックで確定できます。

- 事業主借と事業主貸を少ない方の金額で相殺：借方 事業主借 / 貸方 事業主貸
- 本人から現金を戻して事業主貸を精算：借方 現金 / 貸方 事業主貸
- 事業の現金から本人へ支払って事業主借を精算：借方 事業主借 / 貸方 現金

現金処理は実際の授受の確認が必要です。残高変化・連打による重複を検出し、現金不足での全額支払は拒否します。一部金額・普通預金での精算は下書きを確認して確定できます。経費を再計上しないため利益は変わりません。事業主勘定が残るだけで精算が必要になるわけではなく、翌期の元入金への繰越も使えます。[国税庁の事業主借・繰越の説明](https://www.nta.go.jp/taxes/shiraberu/shinkoku/tebiki/2025/pdf/046.pdf)

## AI相談の往復

ChatGPTのAPIキーや有料API接続は不要です。アプリから自動送信はしません。

1. 設定画面で事業プロフィールを入力します。雑所得側にも別の活動内容を登録できます。
2. 「AI税務相談」で質問・対象・添付するデータを選び、プレビュー後にZIPを保存します。
3. ChatGPTへZIPを添付し、`README_FOR_CHATGPT.md` に沿ってJSONファイルで返答してもらいます。
4. 「AIの回答を取り込む」で初回レビューを読み込みます。
5. 指摘を開き、事実の補足や追加質問を「回答を保存」で記録します。
6. 「対話パックを確認」から履歴付きZIPを渡し直します。
7. 返ってきた対話用JSONを「追加回答を取り込む」で同じスレッドに戻します。

相談プロンプトは暫定的な法的・税務的評価、適用要件、別解釈、根拠、具体的な確認質問を扱います。対象年度の国税庁・e-Gov等の一次情報を参照するよう求め、事実と仮定を分けます。回答の正しさをアプリが保証・自動確定することはありません。雑所得パックでは所得区分も明示し、青色申告特別控除を自動適用しません。

## Google Drive設定

1. Google Cloudでプロジェクトを作成し、Google Drive APIを有効化します。
2. OAuth同意画面を設定します。個人利用のテスト環境では、自分をテストユーザーに追加します。
3. OAuthクライアントを「ウェブアプリケーション」で作成します。
4. 承認済みJavaScript生成元へアプリの生成元を追加します。ローカルでは `http://127.0.0.1:5173` と `http://127.0.0.1:4173`、公開時には実際のHTTPS生成元です。パスは含めません。
5. 発行されたClient IDをアプリの設定画面、または `.env.local` の `VITE_GOOGLE_CLIENT_ID` に設定します。**Client Secretは入力しません。**
6. アプリから接続し、必要なら保存先のルートフォルダIDを設定します。空欄ならアプリ専用フォルダを作ります。

使用スコープは `drive.readonly`、`drive.file`、`drive.appdata`。外部追加ファイルの発見と原本のハッシュ計算には全体の読み取りが必要です。書き込み・新規アップロードにはアプリ作成ファイルの権限を使い、既存原本の更新・削除APIは実装していません。トークンはメモリ内のみで、リロード・期限切れ後は再接続が必要です。

事業用は「確定申告_青色コンパス/年度」、雑所得用は「雑所得_青色コンパス/雑所得/年度」が既定です。両方に同じルートを指定しても雑所得は追加の「雑所得」サブフォルダに分離します。大きな権限の審査・同意画面・テストモード等の制限はGoogle側の設定に従います。

[Google Driveスコープ](https://developers.google.com/workspace/drive/api/guides/api-specific-auth) / [Google OAuthトークンモデル](https://developers.google.com/identity/oauth2/web/guides/use-token-model)

## データと安全性

- 正式な帳簿履歴・バックアップはGoogle DriveのappDataFolderへ保存します。ブラウザ内SQLiteは編集用の作業データです。sql.jsのSQLite WASMを使い、変更単位でOPFSへ保存し、非対応環境ではIndexedDBを使います。
- 各書き込みでWeb Locksを取得し、最新の永続データを再読込、SQLトランザクション、永続化の順で処理します。別タブの古い仕訳の上書きを検出します。BroadcastChannelで更新を通知します。
- 保存失敗を成功扱いせず、以前の保存済みデータを維持します。OPFSはwrite/closeによるファイル更新です。
- SQLiteスキーマは `PRAGMA user_version` とマイグレーションで管理します。
- 原本は端末のIndexedDBに先行保存し、アップロード完了後も保持します。SQLiteバックアップには原本Blobを含みません。未アップロード原本は設定画面で別にZIP保存できます。
- 複数端末の編集は変更履歴の因果関係で合成し、同じ項目の競合は確認待ちにします。同期中に追加された編集を古い結果で上書きしません。接続中は変更後と30秒間隔で自動同期します。
- PWAはアプリのファイルだけをキャッシュします。Googleの認証・Drive API・原本をService Workerで横断キャッシュしません。
- 無料の外部分析SDK・広告・外部フォントはありません。
- AIパックはアプリの設定・トークンを含めず、屋号・原本のファイル名は既定で除外します。数字列・メール等の簡易マスクは完全な個人情報検出ではないため、自由記述もプレビューで確認してください。
- CSVは式として実行され得る文字列をエスケープします。インポートはスキーマ検証とトランザクションで全件成功または全件取消にします。

ブラウザデータを消すとDrive未送信の変更も消えます。「Drive保存済み」を確認してください。バックアップの送信に失敗した場合は成功表示しません。Driveに届いた帳簿は `?recover=1` から復旧できます。アプリ独自の暗号化・暗号鍵には依存せず、Googleのアクセス権と端末のOS保護を使用します。公開GitHubへ帳簿や秘密情報を保存しません。

## 配置・スマホで利用

`pnpm build` の `dist/` をHTTPSの静的ホストに配置します。SPAのパスはハッシュ方式です。GitHub Pages等のサブディレクトリ配置では、ビルド時に `VITE_BASE_PATH=/aoiro-compass/` を設定します。PWAのオフライン機能は本番ビルドで有効です。

スマホではHTTPSのアプリURLを開き、ブラウザの「ホーム画面に追加」で利用します。PCと同じGoogleアカウント・Client IDで接続し、初回はDriveから環境を復旧します。事業所得・雑所得ごとに接続・復旧します。**DriveのClient ID設定と実際の公開URLの登録が必要です。**

GitHub Actionsは型チェック、単体テスト、ビルドを実行します。Pagesへの公開は同梱の手動ワークフローを利用できます。公開サイトに載るのはアプリのコードで、ブラウザ内の会計データはリポジトリへ送信しません。

## 初期版の範囲と既知の制約

- これは帳簿・相談準備の初期版です。**公式の青色申告決算書、所得税・消費税の申告書作成、年度別税額計算、e-Tax交換データ・送信は未実装**です。
- 固定資産の税法上の償却額・特例は自動判定しません。確認した額・割合・根拠を登録する方式です。取得仕訳は別途手入力してください。資産の売却・除却の専用画面は未実装です。
- 帳簿PDFは表示中の帳簿をブラウザの「印刷→PDF保存」で作成します。年度ZIPへの全PDF自動同梱は未実装です。
- 過年度の汎用取込は年次集計・仕訳・固定資産に対応します。過年度の原本は対象年度のDrive同期から追加できます。元ソフト固有の完全互換インポータではありません。
- HEIC/HEIFの原本保管に対応し、ブラウザが表示できない場合はDriveまたは端末の対応アプリで開きます。プレビュー用画像変換はありません。
- 一度の原本アップロードは25MBまで、ZIPは展開後100MBまで。大容量の再開可能アップロードは未実装です。数万件規模での性能試験はまだ行っていません。
- Drive変更トークンと安定IDを使いますが、取りこぼし防止のため年度フォルダ走査も併用します。大量ファイルでの同期は時間がかかります。
- Drive API・OAuthは実装済みです。テスト用APIで自動同期・バックアップ・破損時と新端末の復旧を検証していますが、ユーザーのOAuthプロジェクト・実Driveを用いた結合試験は未実施です。
- 電子帳簿保存法の優良電子帳簿・スキャナ保存等への適合認証や、税務上の控除適用を保証するものではありません。
- 雑所得の所得区分・必要経費の妥当性は自動判定しません。申告での扱いは実態と対象年度のルールで確認してください。

[国税庁：記帳・帳簿等の保存](https://www.nta.go.jp/taxes/shiraberu/shinkoku/kojin_jigyo/index.htm) / [青色申告制度](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/2070.htm)

## 構成

```text
src/domain/    入力スキーマ・純粋な会計計算
src/db/        SQLiteスキーマ・マイグレーション・業務操作
src/lib/       永続化・所得区分・Drive・CSV・AIパック
src/ui/        画面と対話フロー
tests/         会計・原本・AI取込・対話・繰越の単体テスト
e2e/           実ブラウザの主要フローとオフライン試験
```

元の要件に対し、事業分析・相談対話・雑所得分離を追加し、税制の未検証値を組み込む代わりに年度別の根拠を保持する設計にしています。
